# 队列类型

> MikroTik RouterOS 中的队列类型定义了用于管理数据包流的排队规则，其中 BFIFO 和 PFIFO 等选项提供基本的 FIFO 行为，而 CAKE 和 FQ_CoDel 等高级类型则提供延迟控制和公平带宽分配。选择取决于网络优先级，如简单性、公平性或拥塞管理。

# 队列类型

## 概述

队列类型类似于无类别排队规则（queuing disciplines）的模板——这些算法控制数据包在内存缓冲区中如何被丢弃或排队，以便后续传输。它们对于确保良好的服务质量至关重要，因为不仅能在带宽限制被超出时提供帮助，还会影响延迟等其他方面。

它们的复杂性和属性差异很大。例如，先进先出（FIFO）队列简单且能确保数据包处理顺序的公平性，但可能导致队头阻塞等问题。更复杂的队列类型，如实现公平排队或拥塞避免的类型，可以更有效地管理网络性能，但可能需要更多资源和配置。

因此，队列类型的选择取决于网络的具体需求和特性。

## 队列类型一览

1. **BFIFO（字节先进先出）：**

    - **特性：** BFIFO 是一种简单的面向字节的排队规则，按照数据包到达的顺序及其大小发送数据包。
    - **优点：** 数据包管理的简单性和公平性。
    - **缺点：** BFIFO 可能导致队头阻塞，即一个大包会延迟其后面的所有小包。此外，没有机制来防止拥塞或对数据包进行优先级排序。
2. **PFIFO（数据包先进先出）：**

    - **特性：** 与 BFIFO 类似，但基于数据包而非字节进行操作。
    - **优点：** 易于实现和理解。在数据包数量方面是公平的。
    - **缺点：** 与 BFIFO 一样，存在队头阻塞问题，且没有任何拥塞管理机制。
3. **CAKE（通用应用增强）：**

   - **特性：** 一个全面的队列管理系统，旨在对抗缓冲膨胀并确保公平排队。它结合了 CoDel、FQ 和其他技术。
   - **优点：** 在任何网络条件下都能出色地管理延迟。在消费级宽带连接中尤其有用。
   - **缺点：** 配置比更简单的排队规则复杂。并非适用于所有用例，尤其是在需要精细控制的情况下。
4. **CoDel（受控延迟）：**

   - **特性：** CoDel 旨在通过丢弃数据包来控制队列延迟，从而改善缓冲膨胀问题。
   - **优点：** 擅长管理延迟和避免缓冲膨胀。
   - **缺点：** CoDel 本身不提供公平排队。
5. **FQ\_CoDel（公平排队受控延迟）：**

   - **特性：** 将 CoDel 的延迟管理与公平排队相结合。
   - **优点：** 出色的延迟管理和流之间带宽的公平分配。通常被认为是良好的默认选择。
   - **缺点：** 比更简单的队列规则复杂，这可能使其配置更加困难。
6. **MQ\_PFIFO（多队列数据包先进先出）：**

   - **特性：** MQ\_PFIFO 是 PFIFO 的扩展，支持多个队列。
   - **优点：** 允许为不同类型或优先级的流量设置不同的队列。
   - **缺点：** 仍然存在队头阻塞问题，且缺乏内置的拥塞管理机制。
7. **RED（随机早期检测）：**

   - **特性：** RED 旨在通过在队列变满之前随机丢弃数据包来预测和防止拥塞。
   - **优点：** 有助于防止拥塞，并能提升整体网络性能。
   - **缺点：** 配置可能很复杂，需要根据网络的特定特性进行调整。错误配置可能导致性能下降。
8. **SFQ（随机公平排队）：**

   - **特性：** SFQ 旨在通过将流分配到不同的动态队列中，确保流之间资源的公平分配。
   - **优点：** 有助于防止单个流占用整个连接。
   - **缺点：** SFQ 不管理延迟或拥塞。队列数量也可能增加内存使用量。

在选择排队规则时，您需要考虑网络的特点以及您最优先考虑的因素，如延迟、公平性、简单性或拥塞管理。
