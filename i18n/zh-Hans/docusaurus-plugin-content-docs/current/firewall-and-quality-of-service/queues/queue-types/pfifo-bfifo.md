# PFIFO,BFIFO

> PFIFO 和 BFIFO 是 MikroTik RouterOS 中遵循 FIFO 原则的队列管理策略，其中 PFIFO 按到达顺序处理数据包，而 BFIFO 则基于字节进行带宽分配管理。两者均能确保公平性，但缺乏流量优先级区分，主要区别在于队列大小的度量方式及数据包丢弃行为。

# PFIFO,BFIFO

## 概述

队列类型类似于无类别排队规则（classless queuing disciplines）的模板——这些算法控制数据包在内存缓冲区中如何被丢弃或排队，以便后续传输。它们对于确保良好的服务质量（QoS）至关重要，不仅能在带宽超限时发挥作用，还会影响延迟等其他方面。

队列类型的复杂度和属性差异很大。例如，先进先出（FIFO）队列简单且能确保数据包处理顺序的公平性，但可能导致队头阻塞等问题。更复杂的队列类型，如实现公平排队或拥塞避免的算法，可以更有效地管理网络性能，但可能需要更多资源和配置。

因此，队列类型的选择取决于网络的具体需求和流量特征。

## PFIFO（数据包先进先出）

### 描述

PFIFO（Packet First-In, First-Out）是一种遵循基本队列逻辑的队列管理策略。PFIFO 的核心原则是：最先到达的数据包最先被传输。这种方法简单直接，确保没有任何数据包获得优于其他数据包的特殊待遇。

当数据包进入队列时，它们被放置在队列的末尾（尾部）。当传输空间可用时，队列前端（头部）的数据包首先被传输。如果数据包到达时队列已满，则该数据包将被丢弃或遵循其他策略，具体取决于所采用的整体队列管理策略。

### 特性

- **简单性：** PFIFO 是最简单的队列管理形式之一。它不需要复杂的算法或大量的计算资源，易于实现和理解。
- **公平性：** 所有数据包均被平等对待，无论其来源、目的地或内容如何。先入先出。
- **无优先级区分：** 不具备对特定类型流量进行优先级排序的固有功能。虽然这确保了公平性，但在处理可能需要优先级区分的不同类型网络流量时，这可能成为一个缺点。

### 示例

想象一下邮局前排队的场景。每个排队的人（数据包）代表队列中等待的数据包。排在第一位的人最先被服务，然后是下一位，依此类推。如果邮局过于繁忙且队伍已满，任何新到达的人都必须等待或离开（数据包被丢弃）。

### 结论

虽然 PFIFO 简单直接，但其缺乏流量优先级区分能力可能是一个缺点，尤其是在管理包含不同类型数据的网络流量时。在这种情况下，RouterOS 中提供的更复杂的队列管理算法，如 CAKE、FQ-CoDel 或 PCQ，可能更为适用。

## BFIFO（字节先进先出）

### 描述

BFIFO（Byte First-In, First-Out）是另一种队列管理策略，其工作原理与 PFIFO 类似，但有一个关键区别：BFIFO 基于数据包的大小（即字节数）进行操作，而非数据包的数量。

在 BFIFO 系统中，数据包进入队列时仍被放置在末尾，队列前端的数据包首先被传输。然而，队列大小以字节计算，而非数据包数量。当队列达到其最大字节大小时，任何新到达的数据包将被丢弃，或遵循其他策略。

### 特性

- **基于字节：** 与 PFIFO 不同，BFIFO 以字节为单位计算队列大小，从而能够更精确地控制带宽使用。
- **公平性：** BFIFO 同样确保公平性，因为所有数据包均被平等对待，无论其来源、目的地或内容如何。
- **无优先级区分：** 与 PFIFO 类似，BFIFO 不具备对特定类型流量进行优先级排序的固有功能。

### 示例

以公共汽车作为 BFIFO 系统的示例。公共汽车有最大载客量（类似于队列的字节大小）。即使有人排队等候（数据包），如果公共汽车已满，新乘客也无法上车（数据包被丢弃）。

## 对比：PFIFO 与 BFIFO

虽然 PFIFO 和 BFIFO 都是 FIFO（先进先出）策略并遵循基本队列逻辑，但它们之间存在一些差异：

- **队列大小：** PFIFO 以数据包数量来衡量队列大小，而 BFIFO 以字节为单位计算队列大小。这意味着 BFIFO 会考虑每个数据包的大小，从而能够更精确地控制带宽使用。
- **数据包丢弃：** 在 PFIFO 中，当队列中的数据包数量达到上限时，数据包被丢弃。在 BFIFO 中，当队列的字节大小被超出时，数据包被丢弃，即使这意味着丢弃一个比队列剩余空间更大的数据包。
- **公平性：** PFIFO 和 BFIFO 在数据包传输顺序上都是公平的——先入先出。然而，在数据包大小不一的情况下，PFIFO 可能导致大数据包占用大量资源却与较小数据包受到同等对待的情况。相比之下，BFIFO 基于字节的方法可以提供更均衡的资源使用。
- **复杂度：** 与优先处理特定类型流量的更复杂排队策略相比，这两种策略都较为简单。然而，BFIFO 比 PFIFO 稍复杂一些，因为它需要跟踪队列中所有数据包的总大小。

总体而言，在 PFIFO 和 BFIFO 之间的选择取决于您网络的具体需求以及流量的特征。
