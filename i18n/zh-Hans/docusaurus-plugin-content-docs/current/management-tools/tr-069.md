# TR-069

> 本文档介绍 MikroTik RouterOS 对 CPE WAN 管理协议（CWMP）的实现，用于远程设备管理，涵盖 ACS URL 和认证等配置设置、只读状态监控、重置配置的命令、CWMP 会话详情、基于 BBF 标准的参数数据模型，以及使用 Download RPC 进行固件升级的流程。

# TR-069

TR069-client 实现了 CPE WAN 管理协议（CWMP），用于远程设备管理，该协议由宽带论坛（BBF）标准化。CWMP 通过 IP 网络使用 HTTP(S) 与自动配置服务器（ACS）通信，ACS 可以监控、配置远程设备的属性并更新其固件。该协议通常由 ISP 用于管理 CPE，也可用于网络基础设施设备的管理。

需要 tr069-client 软件包。

### 配置设置

**子菜单：** `/tr069-client`

TR069-client 菜单参数：

##### 可写设置

客户端配置设置。

| 属性 | 描述 |
| :-- | :-- |
| **enabled** | 启用/禁用 CWMP 协议 |
| **acs-url** | ACS 的 URL。示例："[https://example.com:8080/path/](https://example.com:8080/path/)"、"[https://192.168.1.100/](https://192.168.1.100/)"。如果通过 HTTPS 访问 ACS，则必须在客户端[证书存储](../authentication-authorization-accounting/certificates.md)中导入根 CA 证书，以验证 ACS 服务器证书。 |
| **username** | HTTP 认证用户名（CPE 用于"登录"ACS） |
| **password** *[敏感参数](../getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)* | HTTP 认证密码（CPE 用于"登录"ACS） |
| **periodic-inform-enabled** | 启用/禁用 CPE 周期性会话发起。定时器在每次成功会话后启动。当会话由周期间隔启动时，Inform RPC 包含"2 PERIODIC"事件。映射到"Device.ManagementServer.PeriodicInformEnable"参数 |
| **periodic-inform-interval** | 周期通知的定时器间隔。映射到"Device.ManagementServer.PeriodicInformInterval" |
| **client-certificate** | [来自证书存储的证书](../authentication-authorization-accounting/certificates.md)，ACS 可用于额外认证 |

##### 只读设置

用于监控客户端状态的只读参数。

| 属性 | 描述 |
| :-- | :-- |
| **status** | CWMP 的信息性状态。disabled - 协议已禁用，waiting-URL - 协议已启用但未配置 ACS URL，running - CWMP 配置正确，将在事件发生时与 ACS 通信 |
| **last-session-error** | 用户友好的错误描述，指示上次会话未成功完成的原因 |
| **retry-count** | 连续不成功会话的次数。如果 > 0，则 last-session-error 应指示错误。在成功会话、协议禁用或重启时重置为 0 |

##### 命令

| 命令 | 描述 |
| :-- | :-- |
| **reset-tr069-config** | 完全重置并清除 tr069-client 配置和状态（不影响其他 ROS 配置）。当 CWMP 进入无响应/挂起状态且无需重新安装 RouterOS 即可恢复时使用。 |

### CWMP 会话

CWMP 客户端通常在不同事件下与 ACS 发起通信（会话）——首次启动、重启、周期间隔、远程请求、值变更等。在每个会话中，CPE 和 ACS 可以调用 RPC 在对方设备上"执行"。CPE 始终以 Inform RPC 开始，其中包含连接原因、设备信息以及根据配置决定的某些参数值。当 CPE 没有更多内容要发送时，ACS 执行其 RPC（大多数情况下是参数管理 RPC）。

### 参数和数据模型

参数是简单的名称+值对，每个供应商可以决定在其设备中支持哪些参数。所有受支持参数的组合称为数据模型（DM）。BBF 定义了三个根数据模型（TR-098、TR-181:1、TR-181:2），供应商应基于这些模型来支持其参数。**RouterOS 数据模型基于"TR-181 Issue 2 Amendment 11"**。

RouterOS TR069 客户端支持的[参数参考](pathname:///assets/tr069_parameters.html)

### Download RPC

#### RouterOS 更新（1 固件升级镜像）

CWMP 标准定义 CPE 固件可以使用 Download RPC 更新，其中 FileType="1 Firmware Upgrade Image"，并提供可下载文件的单个 URL（支持 HTTP 和 HTTPS）。标准还规定下载的文件可以是任何类型，并且可以应用供应商特定的流程来完成固件更新。由于 MikroTik 的更新是基于软件包的（并且为了额外的灵活性），使用 XML 文件来描述固件升级/降级。目前，XML 配置支持提供多个文件 URL，这些文件将被下载并应用，类似于通过固件/软件包文件上传进行的常规 RouterOS 更新。

以下是一个 RouterOS 捆绑软件包和 tr069-client 软件包更新的示例（不要忘记同时更新 tr069-client 软件包）。XML 文件应放在某个 HTTP 服务器上，CPE 可以访问该服务器进行下载。同时，可下载的 RouterOS 软件包文件也应能以相同方式访问（可以在任何 HTTP 服务器上）。使用 ACS 执行 Download RPC，URL 指向 XML 文件（例如"[https://example.com/path/upgrade.xml](https://example.com/path/upgrade.xml)"），内容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 将下载 XML，解析/验证其内容，从提供的 URL 下载文件并尝试升级。结果将通过 TransferComplete RPC 报告。

:::info
注意

始终进行增量固件更新——首先更新本地测试设备，确保新版本恢复 CWMP 通信且所需 ROS 功能正常。其次，通过增量更新 CPE 组来重复步骤。我们不建议一次性更新所有远程设备。

**警告：** 在生产环境中使用 HTTPS 进行固件管理
:::

#### 配置变更（3 供应商配置文件）

相同的 Download RPC 可用于执行完整的配置覆盖（按标准预期）或配置修改（当 URL 的文件扩展名为".alter"时）。

#### 修改配置

RouterOS 拥有大量配置属性，并非所有内容都可以移植到 CWMP 参数中。因此，RouterOS 提供了执行其强大的脚本语言来配置任何属性的可能性。配置修改（实际上是常规脚本执行）可以使用 Download RPC FileType="3 Vendor Configuration File" 执行，且可下载文件的扩展名为".alter"。这个强大的功能可用于配置任何无法通过 CWMP 参数使用的 ROS 属性。

#### 覆盖所有配置

完整的 ROS 配置覆盖可以使用 Download RPC FileType="3 Vendor Configuration File" 执行，URL 文件名可以是任何名称（".alter"扩展名除外）。

**警告：** 提供的配置文件（脚本）必须足够"智能"，以便在重启后正确应用配置。当使用 Upload RPC 上传配置文件时，这一点尤其重要，因为它只包含导出的值。应手动添加的一些内容：

- 接口显示的[启动延迟](../getting-started/configuration-management/index.md#startup-delay)。
- 用户的隐藏密码。
- [证书](../authentication-authorization-accounting/certificates.md)。

#### RouterOS 默认配置变更（X MIKROTIK 出厂配置文件）

此供应商特定的 FileType 允许更改 RouterOS 默认配置脚本，该脚本在 `/system/reset-configuration` 命令执行时（或通过其他方式重置路由器配置时）运行。

:::warning
注意

如果默认配置脚本被更改，它将不会像通过 Netinstall 工具更改该脚本那样显示在 `/system/default-configuration/print` 中。该命令将始终显示 MikroTik 设置的默认脚本。

**警告：** 请谨慎使用，因为上传脚本的失败可能导致设备无法运行和/或 ACS 无法访问
:::

### FactoryReset RPC

这是一个 CWMP 标准 RPC，执行 RouterOS 配置的出厂重置。重置过程与执行以下命令相同：

```
/system/reset-configuration skip-backup=yes

```

请注意，默认出厂配置可能因设备而异（参见[默认配置](../getting-started/configuration-management/default-configurations.md)），执行此命令将删除所有配置并执行内部存储的默认配置脚本。

### Upload RPC

##### 上传当前配置（1 供应商配置文件）

结果是上传到 ACS 的文件，与 RouterOS 中 `/export` 命令的输出相同。

##### 上传日志文件（2 供应商日志文件）

结果是上传到 ACS 的文件，类似于 RouterOS 中 `/log/print` 命令的输出。

##### 上传默认配置（X MIKROTIK 出厂配置文件）

结果是上传到 ACS 的文件，内容为当前设置的默认配置脚本，该脚本将在执行 `/system/reset-configuration` 命令时运行。它可能与使用 `/system/default-configuration/print` 返回的内容不同。

### 安全性

- HTTP 仅应在安全/私有网络中测试初始设置时使用，因为中间人攻击者可能读取/更改配置参数。**在生产环境中，HTTPS 是必须的**。
- CWMP 的入站连接验证在设计上是安全的，因为 CPE 不会与之前配置的 ACS 之外的任何其他设备通信。Connection Request 仅通知 CPE 与之前配置的 ACS 启动新连接和新会话。

### 为使用 TR069 准备路由器

本最佳实践指南展示了 RouterOS 初始设置的示例，当需要安全/预配置的出厂重置并带有自定义配置时，尤其是在使用 TR-069 时。当用户（或提供商不知情地）将设备配置为不可逆状态时，此指南非常有用。然后可以使用 TR069 FactoryReset RPC、RouterOS `/system/reset-configuration` 命令或路由器上的重置按钮来应用出厂重置配置。

##### 在 Netinstall 上覆盖默认出厂配置

执行 Netinstall 时，可以针对特定需求调整默认配置脚本，并通过覆盖 MikroTik 的默认脚本来安装。希望将 FactoryReset 作为备份手段的提供商应执行此操作，以便在发生无法解决的错误配置时使设备重新"可达"。在 TR-069 场景中，默认配置脚本至少应导入证书、设置 IP 层连接、启用并配置 tr069-client、配置防火墙。之后，其他配置可以由 ACS 执行。

:::warning
在出厂重置时，所有证书也会被移除，因此如果重置后需要证书，默认配置脚本必须导入它们
:::
