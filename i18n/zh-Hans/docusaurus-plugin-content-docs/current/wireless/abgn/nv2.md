# Nv2

> Nv2 是 MikroTik 专有的无线协议，采用 TDMA 技术实现 PtMP 网络中的高效媒体访问，支持 Atheros 802.11n 及旧版设备，无需硬件升级。它提供动态速率选择、QoS、加密、RADIUS 认证和同步功能，但与其他无线协议不兼容。

# Nv2

Nv2 是 MikroTik 为 Atheros 802.11 无线芯片开发的专有无线协议。它基于 TDMA（时分多址）媒体访问技术，与常规 802.11 设备使用的 CSMA（载波侦听多址）技术不同。TDMA 解决了隐藏节点问题并提高了媒体利用率，从而带来更好的吞吐量和更低的延迟——尤其是在 PtMP 网络中。

Nv2 支持 Atheros 802.11n 芯片以及从 AR5212 开始的旧版 802.11a/b/g 芯片，但不支持更老的 AR5211 和 AR5210 芯片。这意味着 11n 和旧版设备可以参与同一网络，无需硬件升级即可部署 Nv2。

Nv2 网络中的媒体访问由 Nv2 接入点（AP）控制。AP 将时间划分为固定大小的“周期”，然后根据 AP 和客户端上的队列状态，动态地将每个周期拆分为下行（AP 到客户端）和上行（客户端到 AP）部分。上行时间进一步根据各客户端的带宽需求进行分配。在每个周期开始时，AP 广播一个调度表，告知客户端何时发送数据以及可以使用多长时间。

为了允许新客户端接入，Nv2 AP 会定期为“未指定”的客户端分配上行时间。新客户端利用此时间间隔向 AP 发起注册。AP 随后估算自身与客户端之间的传播延迟，并开始定期为该客户端调度上行时间以完成注册和接收数据。

Nv2 实现了基于每个客户端的动态速率选择，以及用于数据传输的 ARQ 机制，从而确保 Nv2 链路上的可靠通信。

在 QoS 方面，Nv2 支持可变数量的优先级队列，并内置默认 QoS 调度器。此外，还可以通过基于防火墙规则或通过网络使用 VLAN 优先级或 MPLS EXP 位传播的优先级信息，实现细粒度的 QoS 策略。

Nv2 协议每个接口最多支持 511 个客户端。

## 与其他无线协议的兼容性和共存性

Nv2 协议不兼容于任何其他可用的无线协议或实现，也不基于它们，无论是基于 TDMA 还是其他类型。这意味着 **只有支持并启用了 Nv2 的设备才能参与 Nv2 网络**。

常规 802.11 设备无法识别或连接到 Nv2 AP。支持 Nv2 的 RouterOS 设备（即运行 RouterOS 5.0rc1 或更高版本）在执行扫描命令时会看到 Nv2 AP，但只有在正确配置后才会连接到 Nv2 AP。

由于 Nv2 不使用 CSMA 技术，它可能会干扰同一信道上运行的其他网络。同样，其他网络也可能干扰 Nv2 网络，因为所有非 Nv2 信号都被视为噪声。

关于兼容性和共存性的要点如下：

* 只有 RouterOS 设备才能参与 Nv2 网络。
* 只有 RouterOS 设备在扫描时才能看到 Nv2 AP。
* Nv2 网络会干扰同一信道上的其他网络。
* Nv2 网络可能受到同一信道上任何其他网络的影响，无论是否为 Nv2。
* 启用 Nv2 的设备不会连接到任何其他基于 TDMA 的网络。

## Nv2 与 Nstreme 和 802.11 的比较

### Nv2 与 802.11

Nv2 与 802.11 的主要区别：

* 媒体访问由 AP 调度——这消除了隐藏节点问题，并允许实施集中式媒体访问策略——AP 控制每个客户端使用的时间，并可以根据某种策略为客户端分配时间，而不是让每个设备竞争媒体访问。
* 减少传播延迟开销——Nv2 中没有逐帧 ACK——这显著提高了吞吐量，尤其是在长距离链路上，数据帧和后续 ACK 帧的传播延迟会显著降低媒体利用效率。
* 减少每帧开销——Nv2 实现了帧聚合和分片，以最大化分配的媒体利用率并减少每帧开销（帧间间隔、前导码）。

### Nv2 与 Nstreme

Nv2 与 Nstreme 的主要区别：

* 减少轮询开销——Nv2 AP 不是逐个轮询客户端，而是广播一个上行调度表，为多个客户端分配时间；这可以视为“组轮询”——不会浪费时间逐个轮询每个客户端，从而为实际数据传输留出更多时间。这提高了吞吐量，尤其是在 PtMP 配置中。
* 减少传播延迟开销——Nv2 无需逐个轮询客户端；这允许基于到客户端的估计距离（传播延迟）创建上行调度表，从而使媒体利用最有效。这提高了吞吐量，尤其是在 PtMP 配置中。
* 对延迟有更多控制——减少开销、可调整的周期大小和 QoS 功能允许对网络中的延迟进行更多控制。

## 配置 Nv2

**wireless-protocol** 设置控制选择和使用哪种无线协议。请注意，此设置的含义取决于接口角色（AP 或客户端），而角色取决于接口的 **mode** 设置。下表列出了 **wireless-protocol** 的可能值及其含义。

| 值 | AP | 客户端 |
| :-- | :-- | :-- |
| unspecified | 根据旧的 **nstreme** 设置建立 nstreme 或 802.11 网络 | 根据旧的 **nstreme** 设置连接到 nstreme 或 802.11 网络 |
| any | 与 **unspecified** 相同 | 扫描所有匹配的网络，无论协议如何，使用所选网络的协议进行连接 |
| 802.11 | 建立 802.11 网络 | 仅连接到 802.11 网络 |
| nstreme | 建立 Nstreme 网络 | 仅连接到 Nstreme 网络 |
| Nv2 | 建立 Nv2 网络 | 仅连接到 Nv2 网络 |
| Nv2-nstreme-802.11 | 建立 Nv2 网络 | 扫描 Nv2 网络，如果找到合适的网络则连接，否则扫描 Nstreme 网络，如果找到合适的网络则连接，否则扫描 802.11 网络，如果找到合适的网络则连接。 |
| Nv2-nstreme | 建立 Nv2 网络 | 扫描 Nv2 网络，如果找到合适的网络则连接，否则扫描 Nstreme 网络，如果找到合适的网络则连接 |

请注意，**wireless-protocol** 值 **Nv2-nstreme-802.11** 和 **Nv2-nstreme** **不** 指定某种混合或特殊类型的协议——这些值是为了简化客户端配置而实现的，当客户端必须连接的网络协议可能发生变化时。使用这些值有助于将网络迁移到 Nv2 协议。

大多数 Nv2 设置仅对 Nv2 AP 有意义——Nv2 客户端会自动从 AP 适配必要的设置。以下设置与 Nv2 AP 相关：

* **Nv2-queue-count**——指定 Nv2 网络中使用的优先级队列数量。更多详情请参见 [Nv2 网络中的 QoS](#qos-in-nv2-network)。
* **Nv2-qos**——控制帧到优先级队列的映射策略。更多详情请参见 [Nv2 网络中的 QoS](#qos-in-nv2-network)。
* **Nv2-cell-radius**——以公里为单位指定 Nv2 网络中最远客户端的距离。此设置影响 AP 为客户端发起连接而分配的竞争时隙大小，以及用于估算到客户端距离的时隙大小。如果此设置过小，较远的客户端可能难以连接或出现“ranging timeout”错误而断开。虽然在正常操作期间此设置的影响应可忽略不计，但为了保持最大性能，建议在非必要情况下不要增大此设置，以免 AP 预留实际从未使用的时间，而是将其分配给实际数据传输。
* **tdma-period-size**——以毫秒为单位指定 Nv2 AP 用于媒体访问调度的时间周期大小。较小的周期可能降低延迟（因为 AP 可以更早地为客户端分配时间），但会增加协议开销并因此降低吞吐量。另一方面——增大周期将提高吞吐量，但也会增加延迟。对于特别长的链路，可能需要增大此值以获得可接受的吞吐量。这种必要性可能是因为下行（AP 到客户端）和上行（客户端到 AP）数据之间存在“传播间隙”，在此期间没有数据传输。这个间隙是必要的，因为客户端必须接收来自 AP 的最后一帧——这发生在 AP 传输后的传播延迟之后，然后客户端才能传输——结果，来自客户端的帧在客户端传输后的传播延迟之后到达 AP（因此间隙是传播延迟的两倍）。距离越长，每个周期中所需的传播间隙就越大。如果传播间隙占周期的很大一部分，实际吞吐量可能变得不可接受，此时应增大周期大小，以牺牲延迟为代价。基本上，必须仔细选择此设置的值，以最大化吞吐量，同时将延迟保持在可接受的水平。
* **Nv2-mode**——指定使用动态或固定的下行/上行比率。默认值为“dynamic-downlink”。

“sync-master”——作为 nv2-mode=fixed-downlink 工作（因此使用 nv2-downlink-ratio），但允许从设备同步到此主设备；“sync-slave”——尝试同步到主设备（或已同步的从设备），并从主设备适配 period-size 和 downlink ratio 设置。

* **Nv2-downlink-ratio**——指定 Nv2 下行比率。上行比率根据下行比率值自动计算。使用动态下行模式时，当链路完全饱和时也会使用下行比率。最小值为 20，最大值为 80。默认值为 50。

以下设置对 Nv2 AP 和 Nv2 客户端都有意义：

* **Nv2-security**——指定 Nv2 安全模式，更多详情请参见 [Nv2 网络中的安全](#security-in-nv2-network)。
* **Nv2-preshared-key**——指定要使用的预共享密钥，更多详情请参见 [Nv2 网络中的安全](#security-in-nv2-network)。
* **nv2-sync-secret**——指定用于 Nv2 同步的密钥。主设备和从设备上的密钥应匹配，以建立同步状态。

## 迁移到 Nv2

使用 **wireless-protocol** 设置使得在现有网络中迁移或评估 Nv2 协议变得非常简单，并尽可能减少停机时间。推荐步骤如下：

* 将 AP 升级到支持 Nv2 的版本，但暂时不要在 AP 上启用 Nv2。
* 将客户端升级到支持 Nv2 的版本。
* 将所有客户端配置为 **wireless-protocol=Nv2-nstreme-802.11**。客户端仍将使用之前使用的协议连接到 AP，因为 AP 尚未切换到 Nv2。
* 在 AP 上配置 Nv2 相关设置。
* 如果需要使用数据加密和安全认证，请在 AP 和客户端上配置 Nv2 安全相关设置（请参阅 [Nv2 网络中的安全](#security-in-nv2-network)）。
* 在 AP 上设置 **wireless-protocol=Nv2**。这将使 AP 切换到 Nv2 协议。客户端现在应使用 Nv2 协议连接。
* 如果遇到问题，只需将 AP 上的协议改回之前使用的协议，即可轻松切换回原协议。
* 微调 Nv2 相关设置以获得可接受的延迟和吞吐量。
* 实施 QoS 策略以获得最佳性能。

基本故障排除指南：

* 客户端难以连接或出现“ranging timeout”错误断开——检查 **Nv2-cell-radius** 设置是否适当。
* 长距离链路上吞吐量意外偏低，尽管信号和速率正常——尝试增大 **tdma-period-size** 设置。

## Nv2 AP 同步

此功能允许多个位于同一地点的 MikroTik Nv2 AP 通过减少相互干扰而更好地共存。此功能将同步同一频率上 AP 的发送/接收时间窗口，使所有已同步的 MikroTik Nv2 AP 同时发送/接收。这允许在同一地点为多个 AP 复用相同的无线频率，为频率规划提供更大的灵活性。

要设置 Nv2 同步：

* 对于 Nv2 同步，应选择一个主 Nv2 AP，并指定“nv2-mode=sync-master”以及“nv2-sync-secret”。
* 对于 Nv2 从 AP，应使用与主 AP 相同的无线频率，并指定“nv2-mode=sync-slave”，且“nv2-sync-secret”与主 AP 配置中的相同。
* 当主 AP 启用时，从 AP 将尝试通过匹配指定的“nv2-sync-secret”来搜索主 AP。
* 找到主 AP 后，从 AP 将计算到主 AP 的距离，因为主 AP 可能不在同一地点。
* 然后从 AP 开始作为 AP 运行，并从已同步的主 AP 适配周期大小和下行比率。
* 此外，从 AP 运行后，其他从 AP 可以使用此从 AP 进行同步。
* 从 AP 定期监听主 AP，检查“nv2-sync-secret”是否仍然匹配，并再次适配参数。如果主 AP 接口被禁用/启用，所有从 AP 也将被禁用，并从头开始同步过程。
* 如果主 AP 停止工作，从 AP 也将停止工作，因为它们没有同步信息。

### 配置示例

主 AP：

```
 /interface/wireless/set wlan1 mode=ap-bridge ssid=Sector1 frequency=5220 nv2-mode=sync-master nv2-preshared-key=clients1 nv2-sync-secret=Tower1
```

从 AP：

```
 /interface/wireless/set wlan1 mode=ap-bridge ssid=Sector2 frequency=5220 nv2-mode=sync-slave nv2-preshared-key=clients2 nv2-sync-secret=Tower1
```

## Nv2 网络中的 QoS

Nv2 中的 QoS 通过可变数量的优先级队列实现。队列的传输遵循 802.1D-2004 推荐的规则——仅当所有更高优先级队列为空时才考虑传输。实际上，这意味着首先发送更高优先级队列中的所有帧，然后才考虑下一个队列。因此，QoS 策略的设计必须谨慎，以免更高优先级队列使更低优先级队列饿死。

Nv2 网络中的 QoS 策略由 AP 控制，客户端从 AP 适配策略。在 AP 上，QoS 策略通过 **Nv2-queue-count** 和 **Nv2-qos** 参数配置。**Nv2-queue-count** 参数指定使用的优先级队列数量。帧到队列的映射由 **Nv2-qos** 参数控制。

### Nv2-qos=default

在此模式下，出站帧首先由内置 QoS 策略算法检查，该算法根据数据包类型和大小选择队列。如果内置规则不匹配，则根据帧优先级字段选择队列，如同 **Nv2-qos=frame-priority** 模式。

### Nv2-qos=frame-priority

在此模式下，QoS 队列根据帧优先级字段选择。请注意，帧优先级字段不是头部中的某个字段，因此它仅在数据包由给定设备处理时有效。帧优先级字段必须由防火墙规则显式设置，或由帧转发过程从入口优先级隐式设置，例如从 MPLS EXP 位设置。有关帧优先级字段的更多信息，请参见：

* [EXP 位和 MPLS 队列](../../user-guides/routing-and-networking-protocols/mpls/exp-bit-and-mpls-queuing.md)
* [WMM 和 VLAN 优先级](../../bridging-and-switching/user-guides/wmm-and-vlan-priority.md)

队列根据帧优先级按照 802.1D 推荐的用户优先级到流量类别的映射进行选择。映射取决于可用队列的数量（**Nv2-queue-count** 参数）。例如，如果队列数量为 4，映射如下（请注意此映射与 WMM 使用的映射的相似性）：

* 优先级 0,3 -> 队列 0。
* 优先级 1,2 -> 队列 1。
* 优先级 4,5 -> 队列 2。
* 优先级 6,7 -> 队列 3。

如果队列数量为 2（默认），映射如下：

* 优先级 0,1,2,3 -> 队列 0。
* 优先级 4,5,6,7 -> 队列 1。

如果队列数量为 8（最大可能），映射如下：

* 优先级 1 -> 队列 0。
* 优先级 2 -> 队列 1。
* 优先级 0 -> 队列 2。
* 优先级 3 -> 队列 3。
* 优先级 4 -> 队列 4。
* 优先级 5 -> 队列 5。
* 优先级 6 -> 队列 6。
* 优先级 7 -> 队列 7。

有关其他映射、这些映射的合理性讨论以及推荐实践，请参见 802.1D-2004。

## Nv2 网络中的安全

Nv2 安全实现具有以下功能：

* 使用 128 位密钥的 AES-CCM 硬件加速数据加密。
* 用于密钥管理的 4 次握手（类似于 802.11i）。
* 预共享密钥认证方法（类似于 802.11i）。
* 定期更新的组密钥（用于广播和多播数据）。

作为专有协议，Nv2 不使用 802.11 的安全机制，因此安全配置有所不同。使用 Nv2 协议的接口会忽略 **security-profile** 设置。相反，安全由以下接口设置配置：

* **Nv2-security**——此设置启用/禁用 Nv2 网络中安全的使用。请注意，当 AP 上启用安全时，它将不接受禁用安全的客户端。同样，启用安全的客户端不会连接到不安全的 AP。
* **Nv2-preshared-key**——用于认证的预共享密钥。数据加密密钥在 4 次握手期间从预共享密钥派生。两个设备必须使用相同的预共享密钥才能建立连接。如果预共享密钥不同，连接将超时，因为远端将无法正确解释密钥交换消息。
