# 无线工作站模式

> 本页介绍 MikroTik RouterOS 无线工作站模式，解释它们在 L2 地址处理及桥接适用性方面的差异。涵盖标准工作站模式、用于 WDS 连接的 station-wds 模式及伪桥接模式，并附有适用性矩阵和协议支持详情。

# 无线工作站模式

## 概述

处于任何 *station*（工作站）模式的无线接口都会搜索可接入的接入点（AP）并与其建立连接。工作站与 AP 之间的连接行为会因所使用的 *station* 模式类型而略有不同，因此必须根据具体应用和设备选择正确的模式。本文旨在描述各种可用 *station* 模式之间的差异。

*station* 模式之间的主要区别在于 L2 地址的处理方式以及如何通过无线链路进行转发。这直接影响无线链路作为 L2 桥接基础设施一部分的能力。

如果无需通过无线链路进行 L2 桥接——例如在路由或 MPLS 交换网络中——建议使用基本的 **mode=station** 配置，这将提供最高效率。

特定 *station* 模式的可用性取决于无线网络中所使用的 **wireless-protocol**（无线协议）以及已安装的驱动程序（[`wireless` 或 `wifi-qcom`](/docs/wireless/#which-section-is-for-my-device)）。有关各协议对模式的支持情况，请参阅[适用性矩阵](#applicability-matrix)。即使特定协议不支持某种模式，工作站与 AP 之间仍可能建立连接。但请注意，此类连接在 L2 桥接方面将无法按预期工作。

## 802.11 对 L2 桥接的限制

从历史上看，802.11 AP 设备被设计为能够桥接有线网络段与无线网络之间的帧，但工作站设备不应执行 L2 桥接。

考虑以下网络：

```
[X]---[AP]-(     )-[STA]---[Y]
```

其中 X 到 AP 以及 STA 到 Y 为以太网链路，而 AP 到 STA 通过无线连接。根据 802.11 标准，AP 可以透明地桥接 X 与 STA 之间的流量，但无法桥接 AP 与 Y 之间或 X 与 Y 之间的流量。

802.11 标准规定，工作站与 AP 设备之间传输的帧必须采用所谓的 *3 地址* 帧格式，即帧头包含 3 个 MAC 地址。从 AP 传输到工作站的帧包含以下地址：

- 目的地址——工作站设备的地址，同时也是无线电接收地址；
- 无线电发送地址——AP 的地址；
- 源地址——特定帧的发起者地址。

从工作站传输到 AP 的帧包含以下地址：

- 无线电接收地址——AP 的地址；
- 源地址——工作站设备的地址，同时也是无线电发送地址；
- 目的地址。

考虑到每个帧都必须包含无线电发送和接收地址，显然 *3 地址* 帧格式不适合通过工作站进行透明 L2 桥接，因为工作站无法发送源地址与其自身地址不同的帧（例如来自 Y 的帧），同时 AP 也无法以包含 Y 地址的方式格式化帧。

802.11 包含一种额外的帧格式，即所谓的 *4 地址* 帧格式，专为“无线分布式系统”（WDS）设计——用于无线互连 AP 的系统。在此格式中增加了一个额外地址，生成的帧头包含以下地址：

- 无线电接收地址；
- 无线电发送地址；
- 目的地址；
- 源地址。

此帧格式包含通过无线链路进行透明 L2 桥接所需的全部信息。遗憾的是，802.11 未规定 WDS 连接的建立和管理方式，因此 *4 地址* 帧格式（及 WDS）的任何使用均为实现特定。

不同的 *station* 模式试图解决标准工作站模式的不足，以提供对 L2 桥接的支持。

## *station* 模式

这是标准模式，不支持工作站上的 L2 桥接——尝试将无线接口加入桥接不会产生预期结果。另一方面，此模式可视为最高效的模式，因此如果工作站上无需 L2 桥接——例如在路由或 MPLS 交换网络中——应使用此模式。所有无线协议均支持此模式。

## *station-wds* 模式

此模式仅适用于 RouterOS AP。作为连接协商的结果，AP 上会为指定工作站创建一个独立的 WDS 接口。该接口可视为 AP 与指定工作站之间的点对点连接——从 WDS 接口发送的任何内容都会传送到该工作站（且仅传送到该特定工作站），而工作站发送到 AP 的任何内容都会从 WDS 接口接收（不参与 AP 客户端之间的转发），同时保留 L2 地址。

除使用 802.11 协议连接非 RouterOS 设备的情况外，所有无线协议均支持此模式。当与 802.11 协议一起使用时，该模式采用 *4 地址* 帧格式；对于其他协议（如 nstreme 或 nv2），则使用协议内部机制。

此模式可安全用于 L2 桥接，并通过独立的 WDS 接口在 AP 上提供最大的管理控制能力，例如使用桥接防火墙、RSTP 进行环路检测和避免等。

使用 station-wds 模式时，无法连接到由 CAPsMAN 控制的 CAP。

## *station-pseudobridge* 模式

从无线连接的角度来看，此模式与标准工作站模式相同。它通过工作站中实现的某些服务提供有限的 L2 桥接支持：

- IPv4 数据包的 MAC 地址转换——工作站维护一个 IPv4 到 MAC 的映射表，在向 AP 发送帧时用自身地址替换源 MAC 地址（以便能够使用 *3 地址* 帧格式），并在从 AP 接收帧时用映射表中的地址替换目的 MAC 地址。IPv4 到 MAC 的映射也会为 VLAN 封装帧建立。
- 其余协议的单 MAC 地址转换——工作站从第一个转发的非 IPv4 帧中学习源 MAC 地址，并将其用作反向转换的默认地址——当无法执行 IPv4 到 MAC 映射时（例如非 IPv4 帧或缺少映射），该 MAC 地址用于替换从 AP 接收帧的目的 MAC 地址。

此模式仅限于通过单 MAC 地址转换将数据完整 L2 桥接到连接在工作站上的单个设备，并提供一定的 IPv4 帧桥接支持——将非 IP 协议桥接到多个设备将无法工作。此外，MAC 地址转换将 AP 侧对工作站设备的访问限制为基于 IPv4 的访问——其余协议将通过单 MAC 地址转换处理，工作站本身将无法接收。

除 nv2 外，所有协议均支持此模式，***应尽可能避免使用***。仅当 AP 不支持更好的 L2 桥接模式（例如使用非 RouterOS AP 时）或仅需通过工作站设备将单个终端用户设备连接到网络时，才可使用此模式。

## *station-pseudobridge-clone* 模式

此模式与 *station-pseudobridge* 模式相同，区别在于它使用“克隆”的 MAC 地址连接 AP——即使用 **station-bridge-clone-mac** 参数中配置的地址（若已配置）或第一个转发帧的源地址。这实质上在 AP 上表现为连接在工作站上的终端用户设备直接连接到了 AP。

## *station-bridge* 模式

此模式仅适用于 RouterOS AP，并提供工作站设备上透明的、与协议无关的 L2 桥接支持。当通过 **bridge-mode** 参数启用时，RouterOS AP 接受 *station-bridge* 模式的客户端。在此模式下，AP 维护一个转发表，记录哪些 MAC 地址可通过哪个工作站设备访问。

此模式为 MikroTik 专有，无法用于连接其他品牌的设备。

此模式可安全用于 L2 桥接，除非有特定原因需要使用 *station-wds* 模式，否则为首选模式。使用 station-bridge 模式时，无法连接到由 CAPsMAN 控制的 CAP。
