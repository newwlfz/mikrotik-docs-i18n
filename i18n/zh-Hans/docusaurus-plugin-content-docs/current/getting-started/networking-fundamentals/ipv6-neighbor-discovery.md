# IPv6 邻居发现

> RouterOS 支持 IPv6 邻居发现以及使用 RADVD 进行无状态地址自动配置，遵循 RFC 4861 和 4862 标准。它使主机能够通过路由器通告自动配置 IPv6 地址，其状态包括 tentative（临时）、preferred（首选）、deprecated（弃用）和 invalid（无效）。邻居发现取代了 IPv4 的 ARP 及其他协议，便于路由器发现。

# IPv6 邻居发现

RouterOS 支持 IPv6 邻居发现以及使用路由器通告守护进程（RADVD）进行无状态地址自动配置。

## 标准

- [`RFC 4861`](https://tools.ietf.org/html/rfc4861) - IP 版本 6 (IPv6) 的邻居发现。
- [`RFC 4862`](https://tools.ietf.org/html/rfc4862) - IPv6 无状态地址自动配置

## 节点描述

节点是实施 IPv6 的设备。在 IPv6 网络中，节点分为两种类型：

- **路由器** - 转发并非明确发往自身的 IPv6 数据包的节点。
- **主机** - 任何非路由器的节点。

路由器和主机是 RFC 4861 中定义的两种不同分类，但单个设备可以同时扮演两种角色：转发数据包（路由器）和接收发往自身的流量（主机）。

## 无状态地址自动配置

自动配置有几种类型：

- *无状态* - 地址配置通过接收路由器通告消息完成。这些消息包含无状态地址前缀，并要求主机不使用有状态地址配置协议。
- *有状态* - 地址配置通过使用有状态地址配置协议（DHCPv6）完成。如果 RA 消息不包含地址前缀，则使用有状态协议。
- *两者兼有* - RA 消息包含无状态地址前缀，并要求主机使用有状态地址配置协议。

IPv6 可以自动配置自身，而无需使用 DHCP 等有状态配置协议（[示例](#stateless-autoconfiguration-example)）。

:::info
地址自动配置只能在支持多播的接口上执行。
:::

此过程称为无状态地址自动配置，因为路由器不管理状态。这是一种简单、健壮且有效的方法。

RouterOS 使用 RADVD 定期向同一链路上的所有节点通告链路信息。该信息由 ICMPv6 “路由器通告”数据包承载，包含以下字段：

- IPv6 子网前缀。
- 默认路由器链路本地地址。
- 其他可选参数包括：链路 MTU、默认跳数限制和路由器生命周期。

主机使用通告来配置全局 IPv6 地址和默认路由器。全局 IPv6 地址由通告的[子网前缀](./ipv6-addresses.md)和 EUI-64 [接口标识符](./ipv6-addresses.md#interface-identifier)生成。

您可以通过发送 ICMPv6 路由器请求数据包来请求通告。在 Linux 上，**rtsol** 工具用于发送路由器请求。移动节点应定期发送路由器请求。

### 地址状态

当分配自动配置地址时，它可以处于以下状态之一：

- ***`tentative`（临时）*** - 在此状态下，主机验证地址的唯一性。验证通过重复地址检测完成。
- ***`preferred`（首选）*** - 在此状态下，地址已验证为唯一，节点可以从此首选地址发送和接收单播流量。首选状态的持续时间包含在 RA 消息中。
- ***`deprecated`（弃用）*** - 地址仍然有效，但不用于新连接。
- ***`invalid`（无效）*** - 节点不能再发送或接收单播流量。地址在有效生命周期到期后进入无效状态。

## 邻居发现

邻居发现（ND）使用消息和进程来确定相邻节点之间的关系。与 IPv4 相比，ND 取代了地址解析协议（ARP）、ICMP 路由器发现和 ICMP 重定向，同时提供了额外的功能。

主机使用 ND 来：

- 发现相邻路由器。
- 发现地址、地址前缀和其他配置参数。

路由器使用 ND 来：

- 通告其存在、主机配置参数和链上前缀。
- 通知主机特定目的地有更好的下一跳地址。

节点使用 ND 来：

- 解析正在转发 IPv6 数据包的相邻节点的链路层地址，并确定该地址何时发生变化。
- 确定是否可以与邻居发送和接收 IPv6 数据包。

RFC 4861 定义了五种 ND 消息类型：路由器请求（RS）、路由器通告（RA）、邻居请求（NS）、邻居通告（NA）和重定向。将接口添加到 `/ipv6/nd` 仅激活路由器侧的消息：

- 路由器请求（RS） – 路由器侦听主机发送的 RS，并以路由器通告进行回复。
- 路由器通告（RA） – 路由器发送周期性的主动 RA，并响应其收到的任何 RS。RA 的内容（前缀、标志位图、生命周期、MTU、定时器值）取自每个接口的 ND 设置以及任何 `/ipv6/nd/prefix` 条目。
- 邻居请求（NS） – 当路由器收到针对该接口上其自身任何地址（链路本地、SLAAC 或静态）的 NS 时，它会以邻居通告进行回复。这也涵盖了路由器自身地址的重复地址检测（DAD）。
- 邻居通告（NA） – 响应 NS 而发送（如上所述）。除非明确启用，否则不会发送主动 NA。

终端设备之间的主机到主机 NS/NA 由主机协议栈自动处理，不受 ND 菜单控制。重定向生成是可选的，默认禁用（`redirect=no`）。

## 示例

#### 无状态自动配置示例

```ros
[admin@MikroTik] > ipv6 address print
Flags: X - disabled, I - invalid, D - dynamic, G - global, L - link-local
# ADDRESS INTERFACE ADVERTISE
0 G 2001:db8::1/64 ether1 yes

```

在此示例中，**advertise** 标志已启用，这表明已添加动态 `/ipv6/nd/prefix` 条目。

```ros
[admin@MikroTik] > /ipv6/nd/prefix/print
Flags: X - disabled, I - invalid, D - dynamic
0 D prefix=2001:db8::/64 interface=ether1 on-link=yes autonomous=yes
 valid-lifetime=4w2d preferred-lifetime=1w
```

在直接连接到路由器的宿主机上，我们看到已添加一个地址。该地址由前缀部分（前 64 位）和主机部分（后 64 位）组成，前缀部分从前缀通告中获取，主机部分则根据本地 MAC 地址自动生成：

```ros
atis@atis-desktop:~$ ip -6 addr
 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 16436
inet6 ::1/128 scope host
valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qlen 1000
inet6 2001:db8::21a:4dff:fe56:1f4d/64 scope global dynamic
 valid_lft 2588363sec preferred_lft 601163sec
inet6 fe80::21a:4dff:fe56:1f4d/64 scope link
valid_lft forever preferred_lft forever
```

主机已从路由器接收到 *2001:db8::/64* 前缀，并使用它配置了一个地址。

您还可以使用 RADVD 分发 [DNS](../../network-management/dns.md) 服务器信息：

```ros
[admin@MikroTik] > /ipv6/nd/set [find where interface=all] dns=2001:db8::2 advertise-dns=yes
```

或者，您可以分发您自己的路由器链路本地 IPv6 地址作为 DNS 服务器，并将路由器本身用作 DNS 缓存：

```ros
[admin@MikroTik] > /ipv6/nd/set [find where interface=all] advertise-dns=self
```

如果您通告特定的服务器，那么每个 RA 也将包含路由器自身的链路本地地址作为 DNS 服务器，但会将其标记为已过期的服务器。这是必要的，以便使该服务器失效（如果您之前在 self 和 yes 选项之间更改了设置）。任何正确处理 RA DNS 的客户端都将忽略此服务器，或者如果该服务器是路由器本身，则会使现有服务器失效。

您需要具有路由器通告 DNS 支持的客户端软件才能使用通告的 DNS 信息。

在 Ubuntu/Debian Linux 发行版上，您可以安装 **rdnssd** 软件包，它能够接收通告的 DNS 地址。

```ros
mrz@bumba:/$ sudo apt-get install rdnssd
```
