# IPsec

本节涵盖 IPsec 示例与集成。使用它来配置 IKEv2、预共享密钥和后量子密钥工作流，以及第三方 VPN 连接。

<DocCardList />

**互联网协议安全（IPsec）** 是由互联网工程任务组（IETF）定义的一组协议，用于保护通过不受保护的 IP/IPv6 网络（如互联网）进行的数据包交换。

IPsec 协议套件可分为以下几组：

- **互联网密钥交换（IKE）** 协议，用于动态生成和分发 AH 和 ESP 的加密密钥。
- **认证头（AH）** RFC 4302。
- **封装安全载荷（ESP）** RFC 4303。

## 互联网密钥交换协议（IKE）

互联网密钥交换（IKE）是一种为互联网安全关联和密钥管理协议（ISAKMP）框架提供经过认证的密钥材料的协议。还有其他与 ISAKMP 配合使用的密钥交换方案，但 IKE 是使用最广泛的一种。它们共同提供了主机认证和安全关联（SA）的自动管理手段。

大多数时候，IKE 守护进程处于空闲状态。在两种可能的情况下它会被激活：

存在与策略规则匹配的流量需要加密或认证，但该策略没有任何 SA。策略将此情况通知 IKE 守护进程，IKE 守护进程随后发起与远程主机的连接。IKE 守护进程也可以响应远程连接。在这两种情况下，对等体都会建立连接并执行两个阶段：

- **阶段 1** - 对等体就后续 IKE 消息中使用的算法达成一致，并相互认证。同时生成用于派生所有 SA 密钥以及保护主机间后续 ISAKMP 交换的密钥材料。此阶段应匹配以下设置：
  - 认证方法
  - DH 组
  - 加密算法
  - 交换模式
  - 哈希算法
  - NAT-T
  - DPD 和生存时间（可选）

- **阶段 2** - 对等体建立一个或多个 SA，这些 SA 将由 IPsec 用于加密数据。IKE 守护进程建立的所有 SA 都将具有生存时间值（限制 SA 失效后的时间、该 SA 可加密的数据量，或两者兼有）。此阶段应匹配以下设置：
  - IPsec 协议
  - 模式（隧道或传输）
  - 认证方法
  - PFS（DH）组
  - 生存时间

:::warning
存在两个生存时间值 - 软生存时间和硬生存时间。当 SA 达到其软生存时间阈值时，IKE 守护进程会收到通知并启动另一次阶段 2 交换，以用新的 SA 替换该 SA。如果 SA 达到硬生存时间，它将被丢弃。

**注意：** 如果生存时间到期时 DPD 被禁用，阶段 1 不会重新协商密钥；只有阶段 2 会重新协商密钥。要强制阶段 1 重新协商密钥，请启用 DPD。

**注意：** 已知 PSK 认证在“激进”模式下容易受到离线攻击，然而最近的发现表明，在“主”模式和“ike2”交换模式下也可能发生离线攻击。一般建议是避免使用 PSK 认证方法。
:::

IKE 可选地提供完美前向保密（PFS），这是密钥交换的一种属性，对 IKE 而言意味着，即使长期阶段 1 密钥被攻破，也不会轻易允许攻击者访问通过该阶段 1 建立的 SA 所保护的所有 IPsec 数据。这意味着每次阶段 2 都会生成额外的密钥材料。

密钥材料的生成在计算上非常昂贵。例如，即使在一台非常快的计算机上，使用 modp8192 组也可能需要几秒钟。这通常在每个阶段 1 交换中发生一次，而阶段 1 交换在任何主机对之间只发生一次，然后会保持很长时间。PFS 将这种昂贵的操作也添加到每次阶段 2 交换中。

### Diffie-Hellman 组

Diffie-Hellman（DH）密钥交换协议允许两个没有任何初始共享秘密的方安全地建立一个共享秘密。支持以下模指数（MODP）和 ECP Diffie-Hellman（也称为“Oakley”）组：

| Diffie-Hellman 组 | 名称 | 参考 |
| :-- | :-- | :-- |
| 组 1 | 768 位 MODP 组 | RFC 2409 |
| 组 2 | 1024 位 MODP 组 | RFC 2409 |
| 组 5 | 1536 位 MODP 组 | RFC 3526 |
| 组 14 | 2048 位 MODP 组 | RFC 3526 |
| 组 15 | 3072 位 MODP 组 | RFC 3526 |
| 组 16 | 4096 位 MODP 组 | RFC 3526 |
| 组 17 | 6144 位 MODP 组 | RFC 3526 |
| 组 18 | 8192 位 MODP 组 | RFC 3526 |
| 组 19 | 256 位随机 ECP 组 | RFC 5903 |
| 组 20 | 384 位随机 ECP 组 | RFC 5903 |
| 组 21 | 521 位随机 ECP 组 | RFC 5903 |

有关标准的更多信息，请参见 [此处](https://www.iana.org/assignments/ipsec-registry/ipsec-registry.xhtml)。

较大的 DH 组提供更强的安全性，但需要更多的 CPU 资源。以下是几个常用 DH 组及其不同安全级别和 CPU 影响：

DH 组 14（2048 位）- 在安全性和 CPU 使用率之间提供了实用的平衡。它提供 2048 位密钥交换，这被认为对大多数现代应用是安全的，并且得到广泛支持。

DH 组 5（1536 位）- 提供的安全级别略低于 DH 组 14，但由于密钥大小较小，CPU 开销较低。在许多场景下仍被认为是可接受的。

DH 组 2（1024 位）- 应谨慎使用，因为它在常用组中提供的安全性最低。虽然它的 CPU 要求较低，但随着计算能力的增强，它更容易受到攻击。通常不建议在新部署中使用。

为了获得最佳安全性，建议使用 **DH 组 19**。它通常被认为既快速又安全。除非为了兼容旧设备而需要，否则通常应避免使用 DH 组 2。

:::info
计算网络基础设施适当安全级别的推荐方法是首先确定所需的安全位数，并估计解密受保护数据需要多长时间。基于这些要求，您可以选择合适的算法。作为参考，请参见 [https://www.keylength.com/en/4/](https://www.keylength.com/en/4/)。
:::

### IKE 流量

为避免 IKE 数据包命中某些 SPD 规则并要求使用尚未建立的 SA（该数据包可能正试图建立该 SA）进行加密的问题，本地发起且 UDP 源端口为 500 的数据包不经过 SPD 处理。同样，目标为本地且 UDP 目的端口为 500 的数据包也不经过入站策略检查。

### 设置流程

要使 IPsec 使用 IKE-ISAKMP 自动密钥协商正常工作，您需要配置策略（policy）、对等体（peer）和提议（proposal）（可选）条目。

:::danger
IPsec 对时间变化非常敏感。如果 IPsec 隧道两端没有同步时间（例如，不同的 NTP 服务器未使用相同时间戳更新时间），隧道将会中断，并且必须重新建立。
:::

## 认证头（AH）

AH 是一种协议，通过添加一个基于数据报中的值计算出的头，来提供对数据报全部或部分内容的认证。数据报的哪些部分用于计算，以及头的位置，取决于使用的是隧道模式还是传输模式。

AH 头的存在允许验证消息的完整性，但不会对其进行加密。因此，AH 提供认证但不提供隐私。另一种协议（ESP）被认为更优越；它提供数据隐私以及其自身的认证方法。

RouterOS 支持以下 AH 认证算法：

- SHA2 (256, 512)
- SHA1
- MD5

### 传输模式

在传输模式下，AH 头插入在 IP 头之后。IP 数据和头用于计算认证值。在传输过程中可能更改的 IP 字段，如 TTL 和跳数，在认证前被设置为零值。

### 隧道模式

在隧道模式下，原始 IP 数据包被封装在一个新的 IP 数据包内。所有原始 IP 数据包都经过认证。

## 封装安全载荷（ESP）

封装安全载荷（ESP）使用共享密钥加密来提供数据隐私。ESP 还支持其自身的认证方案，类似于 AH 中使用的方案。

ESP 对其字段的封装方式与 AH 有很大不同。它不是只有一个头，而是将其字段分为三个部分：

- **ESP 头** - 位于加密数据之前，其位置取决于 ESP 是用于传输模式还是隧道模式。
- **ESP 尾部** - 此部分位于加密数据之后。它包含用于对齐加密数据的填充。
- **ESP 认证数据** - 此字段包含完整性检查值（ICV），其计算方式类似于 AH 协议的工作方式，用于 ESP 的可选认证功能。

### 传输模式

在传输模式下，ESP 头插入在原始 IP 头之后。ESP 尾部和认证值添加到数据包的末尾。在此模式下，只有 IP 载荷被加密和认证；IP 头不受保护。

### 隧道模式

在隧道模式下，原始 IP 数据包被封装在一个新的 IP 数据包内，从而保护 IP 载荷和 IP 头。

### 加密算法

RouterOS ESP 支持各种加密和认证算法。

#### 认证

- **MD5**
- **SHA1**
- **SHA2 (256 位, 512 位)**

#### 加密

- **AES** - 128 位、192 位和 256 位密钥的 AES-CBC、AES-CTR 和 AES-GCM 算法。
- **Blowfish** - 自 v4.5 起添加。
- **Twofish** - 自 v4.5 起添加。
- **Camellia** - 128 位、192 位和 256 位密钥的 Camellia 加密算法，自 v4.5 起添加。
- **DES** - 56 位 DES-CBC 加密算法。
- **3DES** - 168 位（3 x 56 位）DES 加密算法。

## 策略

策略表用于确定是否应将安全设置应用于数据包。

## 属性

| 属性 | 描述 |
| :-- | :-- |
| **action** (*discard \| encrypt \| none*; 默认值: **encrypt**) | 指定对与策略匹配的数据包执行的操作。none - 原样传递数据包。discard - 丢弃数据包。encrypt - 应用此策略及其 SA 中指定的转换。 |
| **comment** (*字符串*; 默认值: ) | 策略的简短描述。 |
| **disabled** (*yes \| no*; 默认值: **no**) | 策略是否用于匹配数据包。 |
| **dst-address** (*IP/IPv6 前缀*; 默认值: **0.0.0.0/32**) | 要匹配的数据包中的目标地址。适用于使用隧道模式（tunnel=yes）或模板（template=yes）时。 |
| **dst-port** (*整数:0..65535 \| any*; 默认值: **any**) | 要匹配的数据包中的目标端口。如果设置为 any，将匹配所有端口。 |
| **group** (*字符串*; 默认值: **default**) | 此模板分配到的策略组的名称。 |
| **ipsec-protocols** (*ah \| esp*; 默认值: **esp**) | 指定要应用于匹配流量的认证头（AH）和封装安全载荷（ESP）协议的组合。 |
| **level** (*require \| unique \| use*; 默认值: **require**) | 指定如果找不到此策略的某些 SA 时该怎么办：use - 跳过此转换，不丢弃数据包，也不从 IKE 守护进程获取 SA；require - 丢弃数据包并获取 SA；unique - 丢弃数据包并获取仅与此特定策略一起使用的唯一 SA。用于多个客户端位于一个公共 IP 地址后面（NAT 后面的客户端）的设置中。 |
| **peer** (*字符串*; 默认值: ) | 策略应用到的对等体的名称。 |
| **proposal** (*字符串*; 默认值: **default**) | IKE 守护进程将发送以建立此策略的 SA 的提议模板的名称。 |
| **protocol** (*all \| egp \| ggp\| icmp \| igmp \| ...*; 默认值: **all**) | 要匹配的 IP 数据包协议。 |
| **src-address** (*ip/ipv6 前缀*; 默认值: **0.0.0.0/32**) | 要匹配的数据包中的源地址。适用于使用隧道模式（tunnel=yes）或模板（template=yes）时。 |
| **src-port** (*any \| 整数:0..65535*; 默认值: **any**) | 要匹配的数据包中的源端口。如果设置为 any，将匹配所有端口。 |
| **template** (*yes \| no*; 默认值: **no**) | 创建一个模板并将其分配给指定的策略组。模板使用以下参数：group - 此模板分配到的策略组的名称；src-address, dst-address - 请求的子网必须在两个方向上都匹配（例如 0.0.0.0/0 以允许所有）；protocol - 要匹配的协议，如果设置为 all，则接受任何协议；proposal - 用于此模板的 SA 参数；level - 在 NAT 后面有多个客户端的设置中需要 unique 时很有用。 |
| **tunnel** (*yes \| no*; 默认值: **no**) | 指定是否使用隧道模式。 |

## 只读属性

| 属性 | 描述 |
| :-- | :-- |
| **active** (*yes \| no*) | 此策略当前是否正在使用。 |
| **default** (*yes \| no*) | 这是否是默认系统条目。 |
| **dynamic** (*yes \| no*) | 这是否是动态添加或生成的条目。 |
| **invalid** (*yes \| no*) | 此策略是否无效 - 可能的原因是存在具有相同 src-address 和 dst-address 的重复策略。 |
| **ph2-count** (*整数*) | 与此策略关联的活动阶段 2 会话数。 |
| **ph2-state** (*expired \| no-phase2 \| established*) | 密钥建立进度的指示。 |
| **sa-dst-address** (*ip/ipv6 地址*; 默认值: **::**) | SA 目标 IP/IPv6 地址（远程对等体）。 |
| **sa-src-address** (*ip/ipv6 地址*; 默认值: **::**) | SA 源 IP/IPv6 地址（本地对等体）。 |

:::info
策略顺序很重要。它的工作方式类似于防火墙过滤器，策略从上到下执行（优先级参数已移除）。

在隧道模式下，所有数据包都经过 IPIP 封装，其新 IP 头的 src-address 和 dst-address 设置为此策略的 sa-src-address 和 sa-dst-address 值。如果您不使用隧道模式（即使用传输模式），则只有源地址和目标地址与 sa-src-address 和 sa-dst-address 相同的数据包才能由此策略处理。传输模式只能处理源自 IPsec 对等体（建立安全关联的主机）并发送至 IPsec 对等体的数据包。要加密网络之间（或网络与主机之间）的流量，您必须使用隧道模式。
:::

## 对等体

对等体配置设置用于建立 IKE 守护进程之间的连接。然后，此连接将用于协商 SA 的密钥和算法。交换模式是对等体之间唯一的标识符，这意味着只要使用不同的交换模式，就可以有多个具有相同 remote-address 的对等体配置。

## 属性

| 属性 | 描述 |
| :-- | :-- |
| **address** (*IP/IPv6 前缀*; 默认值: **0.0.0.0/0**) | 如果远程对等体的地址与此前缀匹配，则对等体配置用于认证和建立**阶段 1**。如果多个对等体的地址匹配多个配置条目，则使用最具体的那个（即具有最大网络掩码的那个）。 |
| **comment** (*字符串*; 默认值: ) | 对等体的简短描述。 |
| **disabled** (*yes \| no*; 默认值: **no**) | 对等体是否用于匹配远程对等体的前缀。 |
| **exchange-mode** (*aggressive \| base \| main \| ike2*; 默认值: **main**) | 根据 RFC [2408](https://datatracker.ietf.org/doc/html/rfc2408#section-4.1) 的不同 ISAKMP 阶段 1 交换模式。**main** 模式放宽了 rfc2409 第 5.4 节，以允许在主模式下使用预共享密钥认证。ike2 模式启用 Ikev2 RFC 7296。IKEv2 忽略的参数包括 proposal-check、compatibility-options、lifebytes、dpd-maximum-failures、nat-traversal。 |
| **local-address** (*IP/IPv6 地址*; 默认值: ) | 阶段 1 应绑定到的路由器本地地址。 |
| **name** (*字符串*; 默认值: ) |  |
| **passive** (*yes \| no*; 默认值: **no**) | 启用被动模式时，将等待远程对等体发起 IKE 连接。启用被动模式还表明该对等体是 xauth 响应者，禁用被动模式则表明是 xauth 发起者。当被动模式被禁用时，如果配置了策略或在阶段 1 期间创建了策略，对等体将尝试自动建立阶段 1 和阶段 2。 |

### 配置文件

配置文件定义了阶段 1 期间 IKE 协商将使用的一组参数。这些参数可能与其他对等体配置相同。

## 属性

| 属性 | 描述 |
| :-- | :-- |
| **dh-group** (*modp768 \| modp1024  \| modp1536 \| modp2048 \| modp3072 \| modp4096 \| modp6144 \| modp8192 \| ecp256 \| ecp384 \| ecp521*; 默认值: **modp1024,modp2048**) | Diffie-Hellman 组（密码强度） |

| **name** (*字符串*; 默认值: ) |  |
